# v2.0 Platform Readiness & Architecture Decision Records (ADRs)

## 1. ADR Template
All major architectural changes must submit an ADR following this format:
- **Title**: ADR-[Index]: [Short Name]
- **Status**: [Proposed | Approved | Rejected | Deprecated]
- **Context**: Problem statement, constraints, options considered.
- **Decision**: Selected solution and rationale.
- **Consequences**: Positive and negative implications.

## 2. RFC (Request for Comments) Process
- **Drafting**: Authors submit a markdown proposal in `/docs/rfcs/`.
- **Review**: Minimum 7-day review period for team comments.
- **Resolution**: Merged as "Approved" or archived.

## 3. Refactoring Schedule & Technical Debt
- **Refactoring Allocation**: 20% of engineering bandwidth per sprint is reserved for refactoring tasks listed in the known issues registers.
